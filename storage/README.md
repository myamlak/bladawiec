# storage — libqcx-storage

The persistence module: the HDF5 disk-integral engine (`EriStore`),
the drop-in `CachedEriBatchEngine` decorator, SCF checkpoint save/load, RI-tensor
save/load, and the fingerprint/schema plumbing. It does **not** compute
integrals (the cache engine injects an integrals-side engine for misses) and
does not run SCF. As of 2026-08-28 it is a leaf: no other module's build links
`qcx-storage` yet (the io/driver wiring is future work); the disk path is
exercised through its own tests and benchmarks.

Doxygen (the `qcx-docs` target) documents the API; this file is a map, not a
re-documentation.

## Public headers / key types

- `storage/include/qcx/storage/`: `eri_store.hpp`,
  `cached_eri_batch_engine.hpp`, `scf_checkpoint.hpp`, `ri_tensor_store.hpp`,
  `fingerprint.hpp`, `schema.hpp`
- `EriStore` — the append-only HDF5 integral store with FNV-1a-64 chunk
  checksums and the 8.6 derived slots.
- `CachedEriBatchEngine` — the disk-backed drop-in decorator.
- `SaveScfCheckpoint` / `LoadScfCheckpoint` — bit-identical round-trip restart.
- `SaveRiTensor` / `LoadRiTensor` — the RI-3c tensor layout.
